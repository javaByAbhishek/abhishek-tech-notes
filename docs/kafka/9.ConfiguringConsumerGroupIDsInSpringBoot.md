# Configuring Kafka Consumer Group IDs in Spring Boot

## Overview
Demonstrates how to assign a Kafka consumer microservice to a specific consumer group. It covers **three distinct methods** to achieve this configuration, detailing how to transition from hardcoded annotations to dynamic property-driven configurations using custom properties.

---

## Method 1: Using the `@KafkaListener` Annotation

The quickest way to assign a Kafka consumer to a consumer group is by modifying the event handler class directly via the `@KafkaListener` annotation.

### Step-by-Step Implementation:
1. **Navigate to the File:** Locate the `ProductCreatedEventHandler` class under the file path:
   `email-notification-microservice -> source -> main -> java -> handler package`
2. **Analyze the Baseline:** Initially, the `@KafkaListener` annotation is configured with a single property:
   ```java
   topics
   ```
3. **Add the Group ID Property:** To assign the listener to a consumer group, append a second property called `groupId` inside the annotation parentheses, separated by a comma:
   ```java
   @KafkaListener(topics = "...", groupId = "product-created-events")
   ```
    * *Note:* Since this microservice application consumes product created events, naming the group **`product-created-events`** is logical, though any valid string name can be chosen.

---

## Method 2: Using the Consumer Factory Configuration Bean

Alternatively, the Group ID can be configured globally for the consumer factory inside a configuration class instead of hardcoding it within individual annotations.

### Step-by-Step Implementation:
1. **Clean up Previous Config:** Remove the `groupId` configuration property from the `@KafkaListener` annotation in the event handler class.
2. **Navigate to the Configuration Class:** Open `KafkaConsumerConfiguration` located in the root package of the application.
3. **Locate the Factory Method:** Inside this class, look for the method named `consumerFactory`.
4. **Apply Group ID Configuration:** Inside `consumerFactory`, map the configuration using the key:
   ```java
   ConsumerConfig.GROUP_ID_CONFIG
   ```
5. **Dynamic Value Retrieval:** Instead of hardcoding the string value, configure the `Environment` object to read the value dynamically from the `application.properties` file.

---

## Method 3: Using the `application.properties` File (Standard vs. Custom Approach)

Spring Boot allows the Kafka Consumer Group ID to be configured natively through the `application.properties` file, which is located in:
`source -> main -> resources -> application.properties`

### 1. The Native Spring Kafka Way
* The standard, out-of-the-box property name defined in official documentation is:
  ```properties
  spring.kafka.consumer.group-id=product-created-events
  ```
* **Behavior:** If this precise property name is utilized in `application.properties`, you can completely omit the group ID configuration from the `consumerFactory` bean. Spring Boot automatically detects and applies it.

### 2. The Custom Property Way
To make it clear and explicit that the `consumerFactory` bean is actively controlling the configuration, you can choose to use a custom property name that Spring does not natively look for.

* **Problem/Rationale:** Using the standard `spring.kafka.consumer.group-id` property makes it ambiguous whether the configuration is coming from the bean or Spring Boot's automatic defaults. There is no property named `consumer-group-id` in native Kafka documentation, making it explicitly clear that it is a custom configuration.
* **Chronological Flow of the Refactoring:**
    1. Open the `application.properties` file.
    2. Strip away the native prefix (`spring.kafka.`) from the existing line.
    3. Change the property declaration to the custom name:
       ```properties
       consumer-group-id=product-created-events
       ```
    4. Save the changes to `application.properties`.
    5. Go back into `KafkaConsumerConfiguration`.
    6. Update the `consumerFactory` method's code to force the environment object to read this newly created custom property:
       ```java
       // Example logical lookup inside the bean
       environment.getProperty("consumer-group-id")
       ```
    7. Save the changes to the `KafkaConsumerConfiguration` class.

---

## Summary of the Three Methods
* **Method 1:** Add `groupId` directly inside the `@KafkaListener` annotation parameter list.
* **Method 2:** Define `ConsumerConfig.GROUP_ID_CONFIG` programmatically within the `consumerFactory` configuration bean.
* **Method 3:** Declare the native `spring.kafka.consumer.group-id` property inside `application.properties` to let Spring Boot wire it automatically.
